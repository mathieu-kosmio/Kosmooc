## Les six boucles

Prototype = test, erreur, règle, nouveau test.

1. Donner un exemple réel. 2. Décrire la sortie attendue. 3. Faire produire une V0. 4. Comparer. 5. Transformer chaque erreur en règle ou contrôle. 6. Retester sur un nouvel exemple.

## Le prompt métier en six blocs

| Bloc | Vient de |
|---|---|
| Rôle | Contexte (module 2) |
| Mission | Transformation (T) |
| Sources | Entrée (E) |
| Règles | Contraintes (module 2) |
| Sortie | Sortie (S) |
| Contrôle | Contrôle (C) |

## Le test décisif

Second document, représentatif mais différent. On lance **sans modifier les règles**. On mesure : champs corrects, erreurs, informations manquantes, temps gagné estimé. On classe les écarts : règle manquante, donnée absente, cas particulier, erreur de l'IA. On décide : utilisable, à améliorer, à re-spécifier.

## Le harnais

Règles, savoir-faire, gabarits, outils, contrôle qualité, validation. Il reste quand on change de modèle. Journal des corrections : erreur, cause, règle, date. Une correction qui revient deux fois devient une règle, et le document devient un cas de test.

> **À retenir.** Le prototype se juge sur un document qu'il n'a jamais vu. Chaque erreur devient une règle écrite, datée et transportable.

## Exercice en résumé

Quarante-cinq minutes. Écrivez le prompt en six blocs, lancez-le sur le document de référence, tenez le journal des corrections, puis testez sur un second document (devis DEV-2026-0455 pour le cas devis). Livrable : prompt, tableau de test, décision.
